# Note · 个人记账本

软件工程现场编程项目，用于记录日常收入与支出、查看账单并进行收支统计。

> 当前状态：开发计划与六人任务分配。以下目录、接口及功能为约定方案，尚未实现；运行说明、截图和演示视频在联调完成后补充。
> 成员姓名、学号及 GitHub 账号尚未提供，暂用 1—6 号标识，请各成员认领后填写。

## 一、项目目标与技术方案

- 基础记账：记录日期、金额、收支类型、类别及备注。
- 数据保存：使用本地 JSON 文件，重启程序后数据仍可读取。
- 查看记录：展示最近账单，并支持日期、类别、金额和收支类型筛选。
- 收支统计：按筛选条件计算总收入、总支出、结余，并按类别、月份汇总。
- 用户界面：采用本地 Web 页面，提供录入表单、账单列表和统计看板。
- 可选加分项：分类支出图、月度收支图；先保证基础功能可演示。

建议技术栈：Python 3.10+、Flask、HTML/CSS、原生 JavaScript、本地 JSON。图表可使用 Chart.js；如使用，应将依赖保存在本地，方便离线演示。

## 三、模块对接约定

### 数据格式

单条记录统一使用以下字段，金额按整数“分”保存；前端输入和展示使用“元”。

```json
{
  "id": "唯一字符串",
  "date": "2026-11-07",
  "type": "expense",
  "amount": 1250,
  "category": "饮食",
  "note": "午餐"
}
```

- `type` 仅允许 `income` 或 `expense`；金额必须为正整数分，收支方向由类型决定。
- 日期格式为 `YYYY-MM-DD`，由后端验证真实日期。
- 录入时从金额文本精确换算为分，避免直接使用浮点乘法取整。
- JSON 文件计划使用 `data/records.json`，顶层为记录数组。不要提交个人真实账单；演示使用虚构数据。

### 后端接口（计划）

| 方法 | 路径 | 职责 | 负责人 |
| --- | --- | --- | --- |
| GET | `/` | 返回主页面 | 1号、5号 |
| POST | `/api/records` | 新增记录，请求体使用上述业务字段，ID 由后端生成 | 2号 |
| DELETE | `/api/records/<id>` | 删除指定记录 | 2号 |
| GET | `/api/records` | 查询最近记录及组合筛选 | 3号 |
| GET | `/api/stats` | 按相同条件返回统计及图表数据 | 4号 |

- 查询参数统一为 `start_date`、`end_date`、`type`、`category`、`min_amount`、`max_amount`；金额参数单位为分，日期与金额区间均包含端点。
- 列表额外支持 `limit`，默认 10 条；统计对全部符合条件的记录计算，不受列表条数限制。
- 成功响应统一为 `{"data": ...}`；失败统一为 `{"error": "可读错误信息"}`，并返回合适的 HTTP 状态码。
- 列表数据为记录数组；统计数据约定含 `income`、`expense`、`balance`、`by_category`、`by_month`，金额均以分计。
- `by_category` 每项含 `category`、`income`、`expense`；`by_month` 每项含 `month`（YYYY-MM）、`income`、`expense`。
- 1号提供 `load_records()`、`save_records(records)`；2号调用存储接口；3号提供可复用的筛选函数；4号复用该函数，避免列表与统计口径不一致。
- 2号与5号对接录入；3号、4号与6号对接列表和统计。
- 5号在主页面提供录入、筛选、列表、统计和图表容器；6号提前向5号确认所需容器 ID。
- 新增或删除成功后触发 `records-changed` 页面事件，由列表与看板监听并刷新。当前筛选条件由6号统一维护。
